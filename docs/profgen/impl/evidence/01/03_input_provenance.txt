Hand-known boundaries:
  See boundary-golden.json and the explicit encodings/comments in each .s.
  boundaries .text=0x1000; instruction starts relative to .text:
    0,2,6,8,10,18,24,28,32,34.
  Data [14,18) and [22,24) is NOT code; bytes 00 bf decode as NOP if wrongly
  treated as Thumb. A32 literal pool uses e1a00000, also valid instruction data.
  TBB/TBH are four bytes; IT is two bytes and does not alter instruction size.
  Other boundary-* files contain ONE subprogram DIE each, avoiding overlapping
  sibling DWARF function ranges. Discontinuous function: [0x1002,0x1006) and
  [0x1022,0x1024), starts 0x1002,0x1022; prefix at 0x1020 proves the second
  start but is not counted. DWARF addresses are even (no Thumb state bit).
  bad-thumb-start begins at 0x1004, inside MOV.W at 0x1002.
  bad-arm-start begins at 0x101a; bad-a64-start begins at 0x1002.
  bad-thumb-end stops at 0x1004; bad-a64-end stops at 0x1006.
  bad-conflict puts local STT_NOTYPE $a and $t at the same address/section.
  bad-no-map has no mapping symbol; enabling boundary-dependent features fails.
  section-adjacent .plt data ends at 0x1004 and .text Thumb starts there.
  section-same-address deliberately overlaps .plt/.text at 0x1000; use for
  section-keyed boundary unit tests, NOT a positive unique-PT_LOAD integration
  test. The linker uses --no-check-sections explicitly, not a normal binary.
  pure-arm has only $a; pure-a64 has only $x (no $t needed).
  Golden values come from encodings/labels, NOT objdump output.

Paired sample addresses:
  paired-addresses.json records explicit expected virtual addresses.
  a64-multi-load: off 0x1000/0x1004 => VA 0x10000/0x10004;
  off 0x2000/0x2004 => VA 0x30000/0x30004; off 0x1800 hits neither exec segment.
  Formula: VA=p_vaddr+(off-p_offset). No page mask is used.

Probe location pairs (explicit objcopy keep/remove, not a Tizen RPM split claim):
  probe-run.perfbin + probe-run.debug: both probe sections only in runtime.
  probe-debug.perfbin + probe-debug.debug: both only in debug.
  probe-desc-only.perfbin + probe-desc-only.debug: only descriptor in runtime.
  All three are IP rejection inputs, with or without dwarf correlation.

Counting source: counting.c forces unroll 4 with volatile loads; volatile salt
prevents collapsing the two inline call sites. DWARF has two middle inline
instances (call lines 16 and 17), each with two nested leaf instances.
No execution-derived count claim: for synthetic instruction counts c_i and
N=4 duplication, use sum=N*sum(c_i), max=N*max(c_i), avg=N*mean(c_i) when adding
counter tests. This patch supplies binaries, not an implemented profile reader.
