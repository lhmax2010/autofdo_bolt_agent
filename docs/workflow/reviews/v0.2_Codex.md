## 3. 严重问题

### S1 — §8.3 将对数 CI 直接用于百分比阈值，边界结论会不同

**位置：**W §8.3，258–264；附录 A 的 B-S1/A-I3 行（387）。

**问题与依据：**259 明确定义 bootstrap `mean(r)` 的 CI，只有点估计明确变换为 `exp(mean r) − 1`；261–263 随即将“CI”与默认 1% 的 ±ε 比较。若按定义直接比较对数端点，等价区间实际是时间比 `(exp(−0.01), exp(0.01))`，并不是 `(0.99, 1.01)`。如果作者意图使用变换后的 CI，应明确写出，不能让脚本作者自行选尺度。

仅用合成数值即可复现：令 `r = ln(1.010025)`，对数 CI 为 `[r−0.000001, r+0.000001]`：

- 对数端点约为 `[0.0099740830, 0.0099760830]`，直接与 ±0.01 比较得到 **equivalent**。
- 正确变换后的相对耗时 CI 为 `[0.0100239900, 0.0100260100]`，下界超过 +1%，得到 **slower**。

这不是更换统计方法，而是现有判定契约缺少一步变换；即使数值差异很小，也会改变正式结果名称。

**建议修改：**

```diff
- 95% CI from a block bootstrap (...) of mean(r).
+ Obtain the bootstrap interval [L_log, U_log] for mean(r), then report
+ [expm1(L_log), expm1(U_log)] as the relative-time-change CI.
+ The four verdicts below use only this transformed CI and relative ε.
+ Transform the secondary t-interval endpoints in the same way; secondary
+ statistics do not override the primary verdict.
```

也可等价地保留对数端点，并与 `ln(1−ε)`、`ln(1+ε)` 比较；两种实现择一固定即可。同步附录 A 的处理说明，不改变 N、配对、bootstrap 次数或更换主统计量。

**验收：**给判定函数注入上述合成 CI，必须为 slower；增加镜像的 faster 边界、恰好触及 ±ε、跨界及 CI 完全在界内的案例；验证端点变换路径与对数阈值路径一致。无需构建或接板验证此修订。

### S2 — S5 强制要求 coverage warning，会拒绝完全匹配的正确消费构建

**位置：**W S5，134–135；§6 `[consumption]`；M1 验收 352；附录 A 的 B-I8/A-G1 行（395）。

**问题与依据：**“M1: 100 = report every matched function”不符合 LLVM 实现。覆盖率恰好 100% 的函数不会发 warning；135 又把该 warning 与代码改变并列为必需证据，因此一个正常、完全匹配且代码已改变的 AFDO 构建仍无法通过字面门禁。反过来，`0 of N ... were applied` 也可触发 warning，出现 warning 本身不是已应用正计数的证明。

已按本地 LLVM 22.1.8 基准核对：

- `src/llvm/llvm/lib/Transforms/Utils/SampleProfileLoaderBaseUtil.cpp:26–34`：两个阈值默认 0，描述均为 **less than N%**。
- `src/llvm/llvm/include/llvm/Transforms/Utils/SampleProfileLoaderBaseImpl.h:1103–1125`：实际条件是 `Coverage < ...`。诊断输出文件、行及 Used/Total，也不是设计所假设的总会输出目标函数名的完整清单。
- `src/llvm/llvm/lib/Transforms/IPO/SampleProfile.cpp:2299–2322`：找不到非空 Samples 时不进入 `emitAnnotations`；无警告也不能反推成功。
- 已有可用的正面记录：`SampleProfileLoaderBaseImpl.h:428–443` 在找到样本并标记使用时发 `AppliedSamples`，含 `NumSamples`；`llvm/test/Transforms/SampleProfile/remarks.ll:96–106` 展示结构化记录中的 Function、源位置与样本数。本轮只检查源码和测试内容，未运行测试。
- `Clang.cpp:6277–6282` 证明 W 的 Profi 默认描述已修正，此处不再要求改动。

已提交手动试跑记录 `02_manual_pilot_rpi4_thumb.md:227,242` 明确该次**未加覆盖诊断选项**，默认 profile 警告为 0；它不能证明 W 所新增的 mandatory-warning 门禁有效，也不能据此推断开阈值 100 后真实 FFmpeg 必然无警告。本问题依据是确定的源码分支，不虚构当前 workload 的诊断结果。

**建议修改：**

```diff
- (M1: 100 = report every matched function)
+ (M1: 100 warns only for functions below 100%; fully covered functions
+ may be silent. Warnings are diagnostics, not a mandatory success signal.)
- Positive consumption evidence is required: coverage warnings that name
- target functions (proving the profile matched), and target DSOs whose
- code differs from BASE. "No warnings" is never evidence of consumption.
+ Record the actual sample-use compiler arguments and the locked profile
+ SHA verified inside the chroot. For each claimed optimized target DSO,
+ retain positive application evidence: an AppliedSamples optimization
+ record with NumSamples > 0 attributable to that DSO's build unit and
+ source function, or a coverage diagnostic with Used > 0 whose source
+ location is unambiguously resolved to that build unit/function.
+ Also retain the target code difference against the selected control
+ (BASE or BASE-r). Absence of coverage warnings alone neither passes nor
+ fails consumption. If application evidence is unavailable, consumption
+ remains unverified and the stage stops with that reason.
```

取证可复用已有 sample-profile optimization records，不要求加新 LLVM 选项。若增加仅用于记录的编译参数，把它们加入 §9.1 的已声明诊断参数差异；若通过单独取证构建取记录，则核对其目标产物与正式 AFDO 产物相同。`fail_on_coverage_warning=false` 与诊断阈值可保持不变。同步附录 A 对 I8 的处理，不以成功编译或“没有警告”替代消费证明。

**验收：**合成 TU/profile 至少覆盖：100% 匹配且无 coverage warning 但有正数 AppliedSamples；部分匹配且 Used>0；函数存在但 Used=0；名字错配无 Samples；阈值 0；两个目标 DSO 中只有一个有应用记录。前两类允许形成正面应用证据，后三类不能凭警告存在、成功退出或其他 DSO 的记录通过该目标门禁；代码差异检查另行保留。
