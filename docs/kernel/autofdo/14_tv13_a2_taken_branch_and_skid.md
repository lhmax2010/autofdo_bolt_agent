# TV 板 .13：A2 的 r0c 语义与用户态采样探针

2026-11-18（America/Los_Angeles）。pinned、仅用户态的 A/B/C 计数 15/15 有效，结果支持 `r0c` 对已采纳条件分支、无条件直接跳转以及本次测过的调用/返回计数。未采纳条件分支没有产生按 N 增长的计数。D 的 `r0c` 样本强烈偏向长块，**本轮不能确定 IP 所对应的触发分支或实际跨块 skid，不能据此把 IP 直接当作分支目标来生成 A2 边计数。** [前序 PMU 占用报告](13_tv13_pmu_occupancy_and_sampling.md) · [证据索引](evidence/14-tv13-a2/index.json)

## PMUMON 影响

逐次记录 perf 前后的 PMUMON 行和 `arm-pmu` IRQ 统计。计数短槽位通常只跨 0–1 条日志，D 的两种事件每段均有 4 条。记录的 PMUMON 相邻间隔最大约 **5.001 秒**，未见缺行或报错。pinned `r0c:uD` 的两次 D 采集中，主要负载时 CPU3 Core 约 85%、IPC 0.82–0.94、Stall 4%–11%，未见同期同类异常。

**pinned `cycles:uD` 则在两次 D 采集中都出现 PMUMON 数值突变。** 首次 CPU3 Core 降至 0.5%–1.1%、IPC 升至 10.76–22.89、Stall 持续 100%。补采相应三条为 Core 0.3%–2.2%、IPC 5.62–36.59、Stall 100%，同时相同 D 负载仍在运行。采样结束后，162730.226686 的下一条完整窗 CPU3 回到 Core 65.6%、IPC 0.44、Stall 29%。两次复现支持 pinned cycles 干扰 PMUMON 的 CPU3 读数。硬件计数器切换机制、PMUMON 对采样的反向影响和样本偏差大小尚未确定。该异常是数值读数突变，未出现显式报错。

## r0c 语义

固定 N=67,108,864。A 每轮一个条件循环分支，共 N−1 次采纳。B 额外加入 N 次恒未采纳条件分支。C 每次再加一条跨过 UDF 的直接无条件跳转，共 2N−1 次采纳。A/B/C 交错各 5 次。全部命令为 `taskset -c 3 ./perf stat -v --no-scale -e r0c:uD,r08:uD,cycles:uD -- ./<程序>`，三个事件在所有计数槽位都得到 running=enabled。匹配返回补充对照中，两版都执行 BL，随后分别直接 B 跳回和 BX LR 返回，各测一次。两者的预计采纳数同为 3N−1。

下表比值的分母为理论 taken 分支数（r0c），或按反汇编计算的动态指令槽数（r08，含未采纳条件分支指令和退出 SVC 槽）。cycles 无固定理论槽数。σ 为样本标准差。

|---|---|---:|---:|---:|---:|
| A | r0c | 5 | 67,108,968.6 | 34.57 | 1.000001574 |
| A | r08 | 5 | 134,217,890.4 | 51.90 | 1.000001180 |
| A | cycles | 5 | 67,386,206.6 | 174,665.41 | — |
| B | r0c | 5 | 67,109,021.2 | 25.14 | 1.000002357 |
| B | r08 | 5 | 268,435,774.6 | 41.19 | 1.000001172 |
| B | cycles | 5 | 138,378,935.2 | 2,206,154.52 | — |
| C | r0c | 5 | 134,218,061.8 | 96.31 | 1.000002494 |
| C | r08 | 5 | 201,326,985.8 | 109.72 | 1.000001936 |
| C | cycles | 5 | 268,901,290.4 | 231,545.53 | — |
| 调用＋直接跳回 | r0c | 1 | 201,327,109.0 | — | 1.000002573 |
| 调用＋直接跳回 | r08 | 1 | 268,436,477.0 | — | 1.000003789 |
| 调用＋直接跳回 | cycles | 1 | 521,730,096.0 | — | — |

## D 的采样位置分布

D 是一个无运行时控制分支前导的静态 A32 ELF，9 位十进制圈数由定长无分支代码解析。主循环 64 块，每圈 1,828 个动态指令槽。4/16/64 条指令的块分别有 21/21/22 个，按固定顺序经过。块中填不改变控制流的算术指令，末尾向下一块显式跳转，块间有不可达 UDF。最后一块含一次递减和条件回跳，最后一圈不采纳。每块起点、长度、下一块和结束分支由主机反汇编生成并核对。

每种事件 11,595,033 圈，周期分别为 10007 和 100003。首次 record 均成功，但记录时漏加 `--sample-cpu`，perf script 因缺 CPU 字段拒绝输出。执行器随即清掉首批 board 数据，故保留退出原文和 IRQ/PMUMON 证据，只补做两次 D。第二次采集为 `perf record -P --sample-cpu --no-buildid-cache --no-buildid -e <事件>:uD -c <周期>`。evlist 核对 pinned=1、exclude_kernel=1、PERF_SAMPLE_CPU 后才导出。有效的原始样本跨度分别为 **19.118 秒 / 20.152 秒**。导出样本全是 CPU3、cpumode U、block-skid 单一 PID，无显式 lost 记录和未解析行。归档 IP 保持 perf 输出的原值，完整 perf.data 和文本输出只留主机 temp，附 SHA。 [D 源码](evidence/14-tv13-a2/block-skid.S) · [64 块地址表](evidence/14-tv13-a2/blocks.json) · [首次导出失败原件](evidence/14-tv13-a2/initial-export-failure.json.gz)

cycles 对照在三组的样本份额为 3.56% / 18.06% / 78.38%，接近由执行指令槽计算的 4.60% / 18.38% / 77.02%。长块内的 cycles 偏移较均匀，短块并非逐指令均匀。PMUMON 对照异常仍是使用这些数字的限制。r0c 近 99.13% 的 IP 落在长块，只有 1.26% 的总体样本在所在块入口，d≤8 为 32.46%。这表明位置有明显的长块偏差，长块内部又相对偏向较早位置。仅靠该分布无法证明观测 IP 对应实际触发跳转的目标。

**真实 skid 的中位数、p90、跨越 4/16/64 指令目标块比例均未能识别。** 若按静态循环从入口开始每 10007 次 taken 划分，理论为 74,156 次 overflow，实际为 74,165 个样本。用 `期望目标块=(样本序号×10007) mod 64` 对观测块检查相对相位，最强单一残值仅 1,216/74,165（1.64%，均匀参照 1.5625%），连固定未知初相位也无法稳定对齐。观测“域外 0”只说明 PC 都落在 D 的某块，不能推出“没有越过短块”。上表的 12/28 与 22/54 是**所在块内位置**，不是物理 skid。

A2 初判是 **计数层可行，直接从采样 IP 还原目标边尚不成立**。当前测得的 r0c 样本有系统性长块偏置，且 PMUMON 的 cycles 对照受干扰。在缺少能绑定触发分支的证据时，不把这些样本折算为边级 profile。 [统计 JSON](evidence/14-tv13-a2/analysis.json) · [压缩原始样本分片索引](evidence/14-tv13-a2/sample-shards.json)
