## 2. v0.2 新增内容中的严重问题

### X1　§9.1 门禁 2 要求"完整编译与链接命令列表"，但 §5 S1 禁止 `V=1`，M1 按原文无法通过

**位置**：§5 S1（"never `V=1`"）、§9.1（build lock 字段与门禁 2）、§14 M1 验收（"build-lock gates pass"）。

**证据**：
- **不带 `V=1` 的日志里没有完整命令。** M1 用作 BASE 的 J2 构建没有 `V=1`，日志 `temp/m1-target-20261114/weekend-j2/thumb-attempt-0/build.log` 中只有 627 行 `CC\t<file>.o` 这样的简写，没有一行完整的 clang 编译命令（A32 日志相同）。M1 记录 §8.3 中 560 条命令的提取，来自带 `V=1` 而失败的 fix1 构建；§9.2 也写明 J2 只是"复用第 8 节同 SHA 实际编译参数核对"。
- **按现有写法门禁取不到输入。** S1 又明确禁止 `V=1`，因为它会被传给 `find-debuginfo.sh`（fix1 的失败原因）。所以门禁 2 没有输入，M1 无法满足"build-lock gates pass"。

**已有的替代证据**（本轮只读核对）：
- 平台 `%{optflags}` 含 `-frecord-gcc-switches`。打包后的调试 ELF 中有 `.GCC.command.line` 节：`thumb-attempt-0/extracted/usr/lib/debug/usr/lib/libavcodec.so.62.11.100.debug`。用 `readelf -p .GCC.command.line` 可以读出 **311 条 clang 编译单元的完整命令**，每条都含 `-funique-internal-linkage-names`，也带源文件名。AFDO 构建的 `-fprofile-sample-use=…` 同样会被记录。
- 构建 root 中保留着 `BUILD/ffmpeg-8.0.1/ffbuild/config.mak`，其中有 `CC`、`CFLAGS`、`ASFLAGS`、`LDFLAGS`、`SHFLAGS`，可以覆盖汇编与链接参数。

**建议修改**（只改定义，不改补丁或 spec，也不引入 `V=1`）：

§9.1 中"the full extracted compile and link command lists"改为：

> C 编译命令取自打包后调试 ELF 的 `.GCC.command.line`（`-frecord-gcc-switches`），逐条比较；汇编与链接参数取自构建 root 的 `ffbuild/config.mak`（包配置声明该文件的路径），逐项比较；两者都要去掉声明的候选专用选项。包没有这类记录时，必须声明另一种取得完整命令的方法，否则门禁 2 记为"未完成"，M1 不能通过验收。

**副作用**：`.GCC.command.line` 的合并节会把完全相同的命令行去重。所以比较的单位是"去重后的命令集合"，不是逐个目标文件，这一点要在门禁中写明。
