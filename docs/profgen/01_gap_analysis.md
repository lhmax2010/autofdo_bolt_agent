# create_llvm_prof 与 llvm-profgen 功能差异及移植建议

本轮只分析，没有修改 LLVM 代码。基线：Google AutoFDO `f95d1a170dfe24ec5ce4117aa4b0f6d836841703`；LLVM 22.1.8 源码 `f999bd406c0a70fe8107aa992164fe6945c5d46a`。源码摘录与负向搜索见 [02_gap_source.txt](evidence/02_gap_source.txt)。下表 `G/` 表示 `temp/autofdo/`，`L/` 表示 `src/llvm/llvm/tools/llvm-profgen/`；所有文件:行号均相对这两个固定提交。

“已有”表示不能列为 Google 独有能力；“不存在”仅指检查到的当前 llvm-profgen 输入/生成路径，不能扩展为 LLVM 库整体不具备此功能。工作量是设计前的相对估计：小＝局部选项/适配/测试；中＝新增 reader 或扩展映射/统计及回归；大＝新二进制格式/AUX 解码、依赖或布局子系统及跨架构验证。均非承诺工期。

## 推荐移植顺序（高到低）

1. **第一优先：无分支 IP 的最小端到端路径**（表 1、12、13、22）。先明确一种带 mmap/目标身份的文本输入，使用现有 LLVM DWARF/SampleProf writer；规定位置计数、事件周期/频率与 MAX/SUM、duplication 的语义。原始输入解析、映射、符号化和 profile 匹配都应有可判定的失败条件。验收复用上轮 RPi5 cycles/cpu-clock 数据，随后补 ARM/Thumb；不能伪造范围、动态上下文、入口次数或间接调用边。
2. **同等高价值：身份校验与 DSO/PIE 地址正确性**（表 7–10）。build-id 优先，名称降级须显式记录；保留 PID/mmap 生命周期、区分同名库与多个加载基址、验证 AArch64 页大小。FFmpeg/GStreamer/Chromium 不能只靠 basename 自动接受 profile。
3. **高价值专项：kernel-rpi 与模块**（表 10–11）。内核镜像先复用现有 --kernel/KASLR 处理；模块 ET_REL 列为独立大任务，不与普通 IP MVP 捆绑。Google `.text` 回退可作参考，但不能据此声称多节模块问题已解决。
4. **高价值规模验证，按需要实施**（表 20、22）。在 Chromium 匹配 ELF/debug 文件上测峰值内存和耗时；优先按采样地址符号化、限制缓存生命周期。保留现有 DWO/DWP、pseudo-probe/CS 功能，不移植逐字节扫描来替代更高效路径。
5. **中期：原始 perf.data reader 与多场景合并**（表 2、5、6、21）。内置解析价值高但工作量大，可独立于第一版纯 IP 文本支持。决定依赖策略后，补跨架构/字节序/截断文件/丢事件与合并权重测试；不能把不同事件和不同 period 的原始计数直接相加。
6. **未来产品板：SPE reader；BRBE 保持现有分支栈链路兼容**（表 3）。当前两板没有 SPE/ETM/分支栈，不作为首轮阻塞。SPE 是统计分支频率而非连续 trace；BRBE 经 perf 输出兼容分支记录后应先验证既有 LBR parser，无需因名字不同重写全部生成器。
7. **较低优先级：符号列表尺寸策略、IP 阈值微调，再考虑 Propeller**（表 16–19）。已有的 extbinary、内联行计数、discriminator、入口/目标、CS 裁剪不重复移植。ETM 与预取/LLC 提示没有当前硬件/消费端需求，本次不列入实施范围。

上述排序是供设计确认的建议，没有开始实现。工作量不能由“Google 有 use_lbr 开关”推成简单移植一个布尔参数：llvm-profgen 的输入枚举、SampleCounter 与 generator 当前围绕范围/分支构建。纯 IP 的统计性质与 LBR 路径还原不同，必须在设计中保留这种区分。

## 已验证与未验证

本轮功能对比是固定源码分析，不运行 create_llvm_prof、不构建 BOLT、不连接开发板。上轮证据已实测 LLVM 22.1.8 对两份纯 IP 输入退出 1，插桩 PGO 可用，见 [spike 报告](../spike/01_afdo_pgo_feasibility.md)。本轮未用 Chromium 或内核数据衡量两工具性能，跨架构/内核模块/SPE 的动态行为仍需后续专项验证。Google 的 perf_data_converter 子模块声明已读取，但未递归构建/验证其全部 ABI 支持；不把架构无关的接口设计当成所有记录格式都已跑通。
